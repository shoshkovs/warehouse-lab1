# Лабораторная работа № 1: система управления складом

Учебный проект на C++17: классы, наследование, фабричный метод, итераторы, глубокое копирование и перемещение объектов.

## Запуск меню

Требуются CMake 3.16 или новее и компилятор с поддержкой C++17. На macOS и Linux:

```sh
./start
```

Скрипт настроит Debug-сборку, соберёт проект, выполнит все проверки CTest и откроет интерактивное меню. При ошибке сборки или тестов запуск остановится.

Сначала программа запросит вместимость двух складов. Работа начинается с первого склада; пункт `7` переключает активный склад. При переносе получателем автоматически становится другой склад.

| Пункт | Действие |
|---|---|
| `1` | Показать товары активного склада через итератор |
| `2` | Выбрать один из шести типов товара и ввести его данные |
| `3` | Удалить товар по ID или индексу, начиная с нуля |
| `4` | Найти товар по ID, категории или цене |
| `5` | Установить цену или изменить остаток на заданную величину |
| `6` | Перенести товар на другой склад |
| `7` | Переключить активный склад |
| `8` | Копировать активный склад во второй с подтверждением замены |
| `0` | Выйти |

Названия товаров могут содержать пробелы. Цена и остаток — целые неотрицательные числа, вес — конечное неотрицательное число; дробная часть веса вводится через точку. Изменение остатка допускает отрицательную величину, но не отрицательный результат и не переполнение `int`.

Ошибочный ввод запрашивается повторно. Ошибки операций, например отсутствующий ID, повторный ID или полный склад, выводятся без завершения меню. Окончание ввода завершает работу; незавершённое добавление товара не сохраняется.

**Данные находятся в памяти и удаляются при выходе. Сохранения в файл нет.** Сообщения самой программы оставлены на английском; инструкция и отчёт написаны на русском.

## Тесты и готовые сценарии

Только сборка и тесты, без открытия меню:

```sh
./start test
```

Пять демонстрационных сценариев по условию лабораторной:

```sh
./start demo
```

Готовые сценарии сохранены и также входят в CTest. Справка: `./start --help`. Скрипт можно вызывать по пути из другой папки; каталог сборки всегда расположен внутри проекта.

<details>
<summary>Ручная сборка и запуск без скрипта</summary>

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
./build/warehouse_demo
```

Для готовых сценариев вместо меню:

```sh
./build/warehouse_demo --demo
```

</details>

## Проверка с санитайзерами

Для Clang/GCC:

```sh
cmake -S . -B build-sanitize -DENABLE_SANITIZERS=ON
cmake --build build-sanitize
ctest --test-dir build-sanitize --output-on-failure
```

## Отчёт

[Отчёт по лабораторной работе](docs/report.md) содержит UML-диаграмму, описание паттернов «Фабричный метод» и «Итератор», объяснение правила пяти, фактические результаты пяти сценариев, тестирование и выводы.

[Исходник UML в формате PlantUML](docs/warehouse.puml). Вывод программы и проверок сохранён в `docs/results/`. Известные ограничения классов перечислены в отчёте; проверки ввода в меню не устраняют автоматически ограничения прямого вызова их методов.

## Структура

- `start` — сборка, тесты и запуск меню или готовых сценариев.
- `include/` — объявления классов и функции запуска меню.
- `src/` — реализации, консольный интерфейс и точка входа.
- `tests/` — проверки классов, логирования и интерактивных сценариев.
- `docs/report.md` — отчёт на русском языке.
- `docs/warehouse.puml` — исходник UML предметных классов.
- `docs/results/` — результаты запуска и дополнительная проверка перемещения.

Копирование заменяет товары и вместимость второго склада. Товары копируются независимо; изменение копии не меняет оригинал. Вместимость задаётся положительным `int`: ноль и отрицательные значения отклоняются также при прямом вызове конструктора.
